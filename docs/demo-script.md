# AI Travel Planner 3-Minute Demo Script

## 0:00-0:20 Opening

大家好，我想展示的是我的 AI Native 产品作品集项目：AI Travel Planner。

它面向第一次自由行去陌生城市的年轻用户，帮助他们在几分钟内生成一份可执行、可修改、预算可控的旅行计划。

我做这个项目的目标不是做一个旅行网站，而是探索一个问题：AI 如何真正帮助用户完成旅行决策，而不是只生成一段攻略文本。

## 0:20-0:50 Product Background

我发现旅行规划最大的痛点不是没有信息，而是信息太多。用户通常会在 ChatGPT、Google Maps、小红书、TripAdvisor、OTA 和表格之间来回切换。

他们收藏了很多地点，但仍然不知道每天怎么安排、路线是否顺、预算是否合理、下雨怎么办、如果临时想改一天该怎么处理。

所以这个产品的核心原则是：Less Chat, More Action。

## 0:50-1:30 Demo: Planner Input

现在进入 Planner 页面。

这里没有使用聊天框，而是用结构化输入帮助用户表达需求。用户可以填写目的地、天数、预算、同行人、兴趣、饮食偏好、交通方式、旅行节奏、必去地点和不想去的地方。

这样设计的原因是：目标用户不一定会写 prompt。如果让他们面对一个空白聊天框，输入质量会不稳定，AI 输出也会不稳定。

产品还提供 Smart Suggestions 和 AI Tips，例如预算过低、时间太短、兴趣冲突时，系统会在生成前提醒用户，帮助提高首次生成质量。

## 1:30-2:05 Demo: Timeline

点击 Generate 后，AI 会输出结构化 TravelPlan JSON，并渲染成 Timeline。

这里的重点不是展示一段文字，而是展示一个可以执行的旅行计划。每一天都有天气、预算、步数、交通次数和总耗时。每个活动都有时间、地点、简介、预算、交通方式和推荐理由。

用户可以展开 Why Recommended，理解 AI 为什么安排这个地点。这是为了提升信任，因为旅行计划不是娱乐内容，用户需要判断它是否真的靠谱。

## 2:05-2:35 Demo: Partial Replanning

接下来展示我认为最 AI Native 的部分：Partial Replanning。

假设用户觉得第三天不想购物，或者当天会下雨。用户不需要重新生成整个行程，只需要打开 Modify Panel，选择修改原因和范围。

AI 不会返回整份新计划，而是返回 JSON Patch，只修改目标 Day 或 Activity。系统会高亮哪些内容新增、哪些内容修改、哪些内容保持不变。

用户还可以锁定必去地点，AI 之后不能修改它。同时支持 Undo、Redo 和 Version History，让用户知道 AI 没有乱改。

## 2:35-2:50 Demo: Workspace

最后，用户可以保存行程，在 Workspace 里查看所有 Trips，继续编辑、复制、删除或恢复历史版本。

这样产品从一次性生成工具变成了一个可以持续使用的旅行工作台。

## 2:50-3:00 Summary

总结一下，这个项目展示了我对 AI 产品的三个判断：

第一，AI 产品不应该只是聊天框，而应该嵌入真实用户任务。

第二，AI 输出必须结构化、可验证、可修改。

第三，用户信任来自解释、控制、可逆和持续保存。

AI Travel Planner 的核心价值是：让第一次自由行用户不用读几十篇攻略，也能快速得到一份可以直接出发的旅行计划。
